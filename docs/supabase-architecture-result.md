# Supabase 부하 개선 적용 결과

2026-11-18 KST 운영 적용. 요구사항은 `supabase-architecture-execution-plan.md`를 따른다.

## 적용 범위

- 개인 조회: 계정 단위 진행 중 요청 공유, 짧은 결과 재사용, 거래·인증 변경 시 무효화, 다른 탭의 변경 알림을 추가했다. 헤더는 경량 보상 요약을 사용하고 마이페이지에서는 본문 결과를 공유한다. 공통 REST 요청도 진행 중 동일 요청을 공유한다.
- 거래 후 갱신: 보상·뽑기·조합·장착 응답에 필요한 업적·일일 상태를 포함한다. 정상 행동은 기존 변경 RPC 1회+전체 조회 2회에서 변경 RPC 1회로 줄었다. 과거에 저장된 거래 응답에는 부족한 정보만 보충한다.
- 업적: 기존 계산 함수를 기준으로 결과를 계정·시즌·규칙별 재사용한다. 원본 변경은 관련 지표를 무효화한다. 정책·규칙·공개 변경과 날짜·예약 공개 경계를 반영한다. 초기 상태는 실제 조회 때 계산하며 보상은 생성하지 않는다.
- 공통 조회: 최근 완료와 전체 스트릭 순위를 공유한다. 공통 데이터 변경 또는 최대 30초 경과 시 다시 계산한다. 개인 데일리 상태와 계정별 보상 검증은 기존 원본을 사용한다. 작은 목록·카탈로그는 기존 경로를 유지했다.
- 자정·동시성: 자동 조회·재시도 시점을 분산하고 숨겨진 화면의 공개 상태 자동 조회를 복귀 시 처리한다. 출석·완료 보상은 사용자별 경제 잠금을 사용하고 챔피언 보상의 날짜 잠금은 유지한다.

## 검증

- `python3 scripts/verify-cosmetic-concurrency.py --shared-reads`: 임시 로컬 PostgreSQL에서 과소 잔액, 같은 요청 재전송, 동시 1/10회 뽑기, 조합 경쟁, 중복 업적/티켓 수령, revision, 원장 일치, 지표 원본 대조, 공통 결과 공유, 이전 함수로 복구를 통과했다.
- `node scripts/verify-cosmetic-client.mjs`: 상태 버전, 중단 거래 복구, 계정 전환, 정상 변경 후 추가 조회 0회, 동시 읽기 공유 검증을 통과했다.
- `node scripts/verify-request-diagnostics.mjs`: 요청 진단·개인정보·동시 갱신 검증을 통과했다.
- `npm run build`와 운영 배포를 통과했다. `/test/mypage/` HTTP 200과 운영 데일리 요약·스트릭 조회를 확인했다.
- 운영 실제 기록으로 440개 업적 지표를 원래 계산과 대조해 모두 일치했다. 최근 완료 결과도 일치했다. 익명 보상 요약 호출과 인증 역할의 캐시 테이블 직접 읽기가 차단됨을 확인했다. 운영에 테스트 계정이나 가짜 거래를 생성하지 않았다.
- 한 실제 계정의 전체 활성 업적 지표를 동일 조건에서 5회 비교했다. 기존 계산 평균 13.95ms, 재사용 경로 평균 3.99ms였다. 소규모 DB 내부 측정으로 API p95나 자정 부하에서의 개선율을 의미하지 않는다.

## 배포 후 오류 수정

01:41~01:47 KST 업적 조회에서 SQLSTATE 25006/HTTP 405가 발생했다. STABLE 컨텍스트 RPC가 PostgREST에서 읽기 전용으로 실행되어 캐시 INSERT가 거부된 오류다. 초기 SQL 직접 검증은 이 API 트랜잭션 설정을 재현하지 못했다. `20261118_cached_context_volatility.sql`로 해당 RPC를 VOLATILE로 수정하고 `20261118_read_only_cache_fallback.sql`로 읽기 전용 호출의 캐시 누락 시 원본 계산을 반환하도록 보완했다. 로컬 회귀 검증에 RPC volatility와 빈 캐시의 읽기 전용 조회를 추가해 통과했다.
