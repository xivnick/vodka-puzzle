# 업적 서버 작업 현황

작업일: 2026-11-05. 기반 구조와 신규 API를 운영 DB에 적용했으며 경제 기능은 비활성 상태다. 기존 완료 API와 운영 화면은 수정하지 않았다.

## 구현·적용 완료

- private 저장 구조 16개 테이블: 지갑·보유·현재 장착·요청·원장·결과·수령·출석·규칙·문제 연결·일반 최초 완료자.
- 고정 아이템 87개, 업적 20개, 보상 단계 22개, 유형·특수 문제 연결 24개.
- 진행도·수령 조건을 기존 완료와 성공 거래에서 계산한다. 별도 업적 진행도·달성 권리·기능 카운터·장착 이력은 없다.
- 실제 현재 데일리 연속을 표시하고 과거에 도달한 단계는 완료 날짜 기록에서 재구성한다.
- 일반 난이도의 하/쉬움·중/중간·상/어려움 표기를 통합 집계한다. 공개 상태·제외 여부를 반영한다.
- 기존 일반 최초 완료자를 고정했다. 탈퇴하면 사용자는 익명화하고 최초 완료 사실은 유지한다. 새 문제는 원본 기록으로 임시 집계하고 수령 시 확정한다.
- 커먼 3개 조합의 ABC/AAB/AAA 규칙, 서버 암호학적 난수, 중복 100/500코인 환급을 구현했다.
- 요청 재전송, 병렬 거래, 잔액·재고 음수, 영구 보유 아이템 소모, 미완료 거래 커밋, 동일 단계 중복 수령을 차단한다.
- 현재 장착·해제와 별도 장착 버전을 구현했다. 멋쟁이는 수령 시 장착 중인지 확인한다.
- 출석 20코인·완료 100코인·챔피언 티켓 수령을 구현했다. 티켓은 기존 초기 지급·지갑·이벤트 제약을 그대로 사용한다.
- 뽑기 가격·반복 코인·챔피언 티켓 수량·기록 소급 정책의 미정 값은 자동 채택하지 않는다. 미설정 실행을 막는다.
- 한 번 활성화한 뽑기 버전의 가격·확률·목록은 변경할 수 없다. 새 버전으로 교체한다.
- 완료 전후의 달성 알림 비교 함수도 준비했다. 아직 기존 완료 API에서 호출하지 않는다.

신규 RPC 9개:

`cosmetic_context`, `achievement_context`, `cosmetic_operation`, `set_cosmetic_equipment`, `draw_cosmetics`, `craft_cosmetic`, `record_site_visit`, `claim_achievement`, `claim_daily_task`.

## 운영 상태와 검증

- `20261105_cosmetic_foundation.sql`, `20261105_cosmetic_service.sql` 순서로 운영 DB에 적용했다.
- enabled=false, 뽑기 설정은 가격 NULL의 draft, 반복 코인·티켓 수량·기록 소급 정책은 미정 상태다.
- 사용자 지갑·재고·거래·수령·출석은 모두 0건이다. 시안 데이터는 이관하지 않았다. 최초 완료자 기준 기록만 기존 원본에서 복사했다.
- 추가 작업 전후 기존 객체 52개의 함수 정의·권한·테이블 열·제약·RLS·정책·애플리케이션 트리거가 동일함을 비교했다. 이번에 확장한 신규 설정 테이블 2개는 비교에서 제외했다. 새 외래 키에 따른 엔진 내부 트리거는 비교 대상이 아니다.
- 기존 완료·티켓 API는 동일하며 공개 RPC 9개만 추가했다. 비활성 RPC는 쓰기 없이 거절한다.
- 운영 PostgreSQL 17에서 전체 마이그레이션을 롤백하는 사전 검증과 적용 후 롤백 검증을 통과했다. 기존 문제를 풀거나 기존 완료를 수정하지 않는다.
- 격리된 로컬 PostgreSQL 16의 실제 RPC 병렬 호출도 통과했다. 100코인 초과 차감, 같은 UUID의 동시 재전송, 1회·10회 동시 뽑기, 같은 언커먼 동시 생성, 재료 경쟁, 미션·챔피언 티켓의 동시 수령, 버전 증가와 원장 일치를 확인했다. 로컬 테스트 클러스터는 종료·삭제했다.
- 추가 경계 검증: 배치 내 중복 환급, 아이콘 해제 후 수령 보존, 현재 수치가 끊긴 과거 연속 보상, 전체 완료 후 문제 추가, 설정 버전 변경과 과거 요청 재현, 계정 격리·삭제.

## 남은 연결 작업

1. 기존 `submit_completion`의 일반 완료 분기에 퍼즐 공통 잠금과 최초 완료자 확정 호출을 연결한다. 수령 전 탈퇴·동시 완료까지 보존하려면 활성화 전에 필요하다.
2. 기존 완료 응답에 새 달성 알림을 연결한다. 기존 필드·중복 제출·타임머신 동작을 보존하고 회귀 검증한다.
3. 실제 마이페이지·꾸미기·공개 랭킹·토스트를 연결한다. 현재 예시 페이지는 가상 데이터로 그대로 둔다.
4. 클라이언트의 자정·계정 전환·응답 역전 처리와 전체 사용자 흐름을 검증하고 기능을 활성화한다.

이 단계들은 기존 서비스 경로를 바꾸므로 이번 비활성 서버 적용과 분리했다. 새 API 자체의 구현을 다음 단계로 미루지는 않았다.

## 확정할 설정·정책

- 반복 업적 코인 보상량.
- 뽑기 가격.
- 데일리 챔피언 티켓 수량.
- 기존 기록 소급: all_records 또는 since_launch와 도입 시각.
- 현재 구현은 전체 완료를 수령 시점의 공개 문제 집합으로 판정하고 수령 후에는 유지한다. 데일리는 당일 신규 수령만 허용한다. 이 두 정책은 활성화 전에 확인하며, 다른 정책을 택하면 해당 판정 코드를 조정한다.
