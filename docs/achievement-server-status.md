# 업적 서버 작업 현황

작업일: 2026-11-05. 기반 구조와 신규 API를 운영 DB에 적용했으며 경제 기능은 비활성 상태다. 기존 완료 API와 운영 화면은 수정하지 않았다.

## 구현·적용 완료

- private 저장 구조 16개 테이블: 지갑·보유·현재 장착·요청·원장·결과·수령·출석·규칙·문제 연결·일반 최초 완료자.
- 고정 아이템 87개, 활성 업적 19개, 활성 보상 단계 21개, 유형·특수 문제 연결 24개.
- 진행도·수령 조건을 기존 완료와 성공 거래에서 계산한다. 별도 업적 진행도·달성 권리·기능 카운터·장착 이력은 없다.
- 실제 현재 데일리 연속을 표시하고 과거에 도달한 단계는 완료 날짜 기록에서 재구성한다.
- 일반 난이도는 정수 0·1·2·3으로 통일했다. 0은 표기 안 함이며 업적은 1·2·3을 직접 집계한다. 공개 상태·제외 여부를 반영한다.
- 기존 일반 최초 완료자를 고정했다. 탈퇴하면 사용자는 익명화하고 최초 완료 사실은 유지한다. 새 문제는 원본 기록으로 임시 집계하고 수령 시 확정한다.
- 커먼 3개 조합의 ABC/AAB/AAA 규칙, 서버 암호학적 난수, 중복 100/500코인 환급을 구현했다.
- 요청 재전송, 병렬 거래, 잔액·재고 음수, 영구 보유 아이템 소모, 미완료 거래 커밋, 동일 단계 중복 수령을 차단한다.
- 현재 장착·해제와 별도 장착 버전을 구현했다. 멋쟁이는 수령 시 장착 중인지 확인한다.
- 출석 20코인·완료 100코인·챔피언 티켓 수령을 구현했다. 티켓은 기존 초기 지급·지갑·이벤트 제약을 그대로 사용한다.
- 데일리 챔피언은 티켓 1장, 일반 문제 기록 소급은 전체 기록으로 확정했다. 미설정 실행을 막는다.
- 한 번 활성화한 뽑기 버전의 가격·확률·목록은 변경할 수 없다. 새 버전으로 교체한다.
- 완료 전후의 달성 알림 비교 함수도 준비했다. 아직 기존 완료 API에서 호출하지 않는다.

신규 RPC 10개:

`cosmetic_context`, `achievement_context`, `cosmetic_operation`, `set_cosmetic_equipment`, `draw_cosmetics`, `craft_cosmetic`, `record_site_visit`, `claim_achievement`, `claim_daily_task`, `set_all_clear_effect`.

## 운영 상태와 검증

- `20261105_cosmetic_foundation.sql`, `20261105_cosmetic_service.sql` 순서로 운영 DB에 적용했다.
- enabled=false, 뽑기 설정은 100코인의 draft이며 반복 보상은 확정값이다. 데일리 챔피언 티켓 1장과 일반 문제 전체 기록 소급도 확정했다.
- 사용자 지갑·재고·거래·수령·출석은 모두 0건이다. 시안 데이터는 이관하지 않았다. 최초 완료자 기준 기록만 기존 원본에서 복사했다.
- 업적 API 추가 배포 전후 기존 객체 52개의 함수 정의·권한·테이블 열·제약·RLS·정책·애플리케이션 트리거가 동일함을 비교했다. 이번에 확장한 신규 설정 테이블 2개는 비교에서 제외했다. 새 외래 키에 따른 엔진 내부 트리거는 비교 대상이 아니다.
- 기존 완료·티켓 API는 동일하며 공개 RPC 9개만 추가했다. 비활성 RPC는 쓰기 없이 거절한다.
- 운영 PostgreSQL 17에서 전체 마이그레이션을 롤백하는 사전 검증과 적용 후 롤백 검증을 통과했다. 기존 문제를 풀거나 기존 완료를 수정하지 않는다.
- 격리된 로컬 PostgreSQL 16의 실제 RPC 병렬 호출도 통과했다. 100코인 초과 차감, 같은 UUID의 동시 재전송, 1회·10회 동시 뽑기, 같은 언커먼 동시 생성, 재료 경쟁, 미션·챔피언 티켓의 동시 수령, 버전 증가와 원장 일치를 확인했다. 로컬 테스트 클러스터는 종료·삭제했다.
- 추가 경계 검증: 배치 내 중복 환급, 아이콘 해제 후 수령 보존, 현재 수치가 끊긴 과거 연속 보상, 전체 완료 후 문제 추가, 설정 버전 변경과 과거 요청 재현, 계정 격리·삭제.

## 남은 연결 작업

1. 기존 `submit_completion`의 일반 완료 분기에 퍼즐 공통 잠금과 최초 완료자 확정 호출을 연결한다. 수령 전 탈퇴·동시 완료까지 보존하려면 활성화 전에 필요하다.
2. 기존 완료 응답에 새 달성 알림을 연결한다. 기존 필드·중복 제출·타임머신 동작을 보존하고 회귀 검증한다.
3. 실제 마이페이지·꾸미기·공개 랭킹·토스트를 연결한다. 현재 예시 페이지는 가상 데이터로 그대로 둔다.
4. 클라이언트의 자정·계정 전환·응답 역전 처리와 전체 사용자 흐름을 검증하고 기능을 활성화한다.

이 단계들은 기존 서비스 경로를 바꾸므로 이번 비활성 서버 적용과 분리했다. 새 API 자체의 구현을 다음 단계로 미루지는 않았다.

## 확정할 설정·정책

- 뽑기 가격 100코인과 반복 보상은 운영 DB에 비활성 상태로 반영했다.
- 데일리 챔피언 티켓은 1장으로 확정·반영했다.
- 일반 문제 도전과제는 출시 전 기록을 포함한다. 일일 과제는 출시일부터 당일 보상만 받는다.
- 데일리는 당일 신규 수령만 허용한다. 전체 완료 효과는 현재 자격에 따라 노출·적용하고, 토글 선택은 독립 보존하는 것으로 확정했다.

## 난이도 정규화 후속 작업

`20261105_numeric_difficulty.sql`로 DB 난이도를 정수 NOT NULL DEFAULT 0, 범위 0~3으로 변경했다. 기존 미지정은 0, 하/쉬움은 1, 중/중간은 2, 상/어려움은 3으로 변환했다. 관리자 RPC도 integer 입력만 받으며, 난이도를 입력하지 않는 이전 메타데이터 수정 RPC는 현재 값을 보존한다. 문제 목록은 0을 숨기고 1~3을 마름모 개수로 표시한다.

정규화 적용 후 DB·관리자 API·공개 목록 JSON·업적 집계를 검증했다. 관리자 저장 0·1·2·3, 범위 밖/NULL 거절, 수정 충돌 방지, 이전 메타데이터 API의 난이도 보존을 확인했다. 관리자 화면과 관련 예시 페이지도 배포했다.

## 전체 완료 효과 변경 (2026-11-06)

`20261106_all_clear_effect.sql`을 비활성 상태로 운영 적용했다. 완전 정복 규칙은 비활성으로 보존하고 목록·달성 알림·신규 수령에서 제외한다. 현재 올클 여부를 원본 기록으로 판정하며 별빛 반짝임은 효과 설정에서만 독립 토글로 제공한다. 선택은 all_clear_enabled에 보존하고 새 공개 문제로 미달성이 되면 숨긴다. 조건 회복 시 이전 선택을 적용한다. 기본색과 다른 효과와의 중첩도 허용한다.

API 롤백 검증과 격리된 동시 호출 검증을 통과했다. 새 공개 문제, 미래/테스트 문제 제외, 다시 완료, 끄기, 일반 장착과 독립 보존, 버전 충돌, 아이템·수령·이력 미생성을 확인했다. 시안은 `customize/?all-clear=1`로 올클 상태, `customize/?all-clear=0`으로 조건 상실 상태를 확인한다. 두 상태를 오가도 켜기·끄기 선택은 유지한다. 실제 계정과 기존 운영 화면은 연결하지 않았다.

## 반복 보상·가격 적용 (2026-11-06)

`20261106_achievement_repeat_rewards.sql`을 적용했다. 반복 시작점과 코인·티켓·랜덤 보상을 추가했다. 꺼지지 않는 불은 7 → 30 → 60…이며, 퍼즐 수집가 100·난이도별 30/60/90·연금술사 100코인, 행운을 빌어요 10~100코인(10단위 균등 추첨)으로 설정했다. 가격 100코인은 draft에만 반영했다. 기능은 계속 enabled=false다.

운영 DB 롤백 리허설과 적용 후 실제 RPC 검증, 격리된 로컬 동시 호출 검증을 통과했다. 랜덤 보상의 결과 고정·중복 수령, 티켓 중복 수령·원장 일치, 30 시작점·60 다음 단계·30/60/90 알림을 확인했다. 실제 사용자 거래·수령은 모두 0건이며 시안은 가상 데이터다.

## 시간 여행자 준비 (2026-11-06)

`20261106_time_traveler_mission.sql`을 적용했다. 기존 이용 기록 3회·계정 전체·아이콘 1회·반복 없음이다. `cosmetic_usage.time_machine_count`와 `time_machine` 지표는 기존 `private.time_machine_openings`만 조회한다. 기록 소급 미정인 일반 풀이와 달리 기존 이용 기록을 그대로 사용한다. 기존 타임머신 개방 API와 티켓 차감 동작은 수정하지 않았다.

아이콘 선택 대기 중인 규칙·아이템을 각각 active=false로 준비했다. 기존 활성 업적은 19개이며 준비한 신규 미션을 포함하면 20개다. 시안은 history를 임시 표시하며 5개 후보를 별도 페이지에서 보여준다. 활성화·지급은 하지 않는다. 원본 기록 2→3, 같은 날짜 중복, 계정 격리, 일회성 수령과 동시 중복 방지를 로컬 및 운영 DB 롤백 검증으로 확인했다.

시간 여행자의 최종 아이콘은 후보 3번 `clock-bolt`(시계와 번개)로 확정했다. `20261106_time_traveler_clock_bolt.sql`로 해당 규칙·아이템의 선택 대기 상태를 해제했다. 활성 규칙은 20개이며 경제 기능 전체의 enabled=false는 유지한다. 테스트 마이페이지·전체 정리에도 같은 아이콘을 적용한다.

## 챔피언·일반 기록 소급 확정 (2026-11-06)

`20261106_achievement_history_champion.sql`로 champion_tickets=1, history_policy=all_records를 적용했다. 기존 일반 풀이를 포함하며 일일 과제의 과거 날짜 수령은 기존 API에서 계속 거절한다. 출시 시각과 기능 활성화는 지정하지 않았다. 운영 DB 롤백 리허설과 적용 후 RPC 검증을 통과했다.
