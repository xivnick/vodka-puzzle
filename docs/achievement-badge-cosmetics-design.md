# 업적 배지 색상·효과 설계

실제 서버 구현은 [업적·코인·꾸미기 서버 설계](achievement-server-design.md)를 따른다. 이 문서의 화면 시안 저장 방식과 운영 서버 저장 방식을 구분한다.

최종 정리: 2026-10-28. 레어 색 조합은 36색이 모두 1~2회 등장하는 수정안을 기준으로 확정한다. 별빛 반짝임은 현재 일반 문제 전체 완료 시 표시되는 별도 켜기·끄기 효과다.

## 기본 구조

업적을 달성하면 아이콘을 얻고, 획득한 색상과 효과로 이름 뒤 배지를 꾸민다. 업적 아이콘과 색상·효과의 획득을 구분한다. 확정한 미션 이름·아이콘·보상 기준은 [업적 미션 설계](achievement-missions-design.md)에 정리한다. 전체 완료 조건부 효과는 이 문서에 기록한다.

| 등급 | 구성 | 획득 | 에픽 효과 적용 |
|---|---|---|---|
| 커먼 | 기본 단색 36종 | 뽑기 | 불가 |
| 언커먼 | 자유로운 두 색 조합 또는 조합으로 만든 단색 | 커먼 3개 조합 전용 | 가능 |
| 레어 | 이름을 붙인 지정 색 조합 24종 | 뽑기 | 가능 |
| 에픽 | 흰색 광택 효과 5종 | 뽑기 | 언커먼·레어 색상 위에 적용 |

뽑기 대상은 커먼·레어·에픽이다. 언커먼은 뽑기에 넣지 않는다. 커먼 단색에 효과를 쓰려면 같은 색 3개를 조합해 언커먼 단색을 만든다.

## 언커먼 조합

- 커먼 3개를 재료로 사용하고 모두 소모한다. ABC는 AB·AC·BC 중 하나를 균등하게 무작위 선택하고, AAB는 반드시 AB, AAA는 반드시 A 단색 언커먼을 만든다. 결과는 조합하기를 누른 뒤에만 정하며 사전에 계산하거나 보여주지 않는다.
- 서로 다른 색이 포함된 경우 재료 색 중 두 색으로 된 언커먼을 만든다. 자유 조합에서는 모든 두 색 조합을 허용한다.
- 같은 색 3개를 사용하면 해당 색의 언커먼 단색을 만든다.
- 단색의 외관은 커먼과 같지만 에픽 효과를 적용할 수 있다.
- 두 색의 2분할·그라데이션, 좌우·대각선 방향은 별도 아이템으로 나누지 않고 표현 옵션으로 취급한다.

현재 팔레트의 순서 없는 두 색 조합은 630종이고, 단색 36종을 더하면 이론상 666종이다. 방향·표현 방식은 이 수에 포함하지 않는다. 이는 가능한 조합 수이며 개별 이름 666개나 뽑기 항목 666개를 확정한 뜻은 아니다.

레어 지정 조합과 같은 두 색도 자유 조합의 허용 범위에 포함된다. 언커먼은 조합, 레어는 지정 조합을 뽑기로 얻는 구조다. 조합 결과를 레어로 자동 승급하는 규칙은 두지 않는 방향으로 정리한다.

## 뽑기 에픽 효과 5종

뽑기로 얻는 동작 효과는 다음 에픽 5종으로 묶는다. 색상을 바꾸지 않고 기존 색 위에 흰색의 투명도를 조절해 광택을 표현한다. 아이콘 자체의 이동·회전·변형은 사용하지 않는다. 별빛 반짝임은 아래 전체 완료 조건부 효과로 구분한다.

| 효과 | 표현 |
|---|---|
| 빛의 띠 | 대각선으로 빠르게 스치는 흰색 광택 |
| 포일 | 작은 면들이 드문드문 반짝인 뒤 기본 색으로 복귀 |
| 간섭광 | 곡선 무늬의 흰색 광택이 물결처럼 밝아짐 |
| 렌티큘러 | 부드러운 세로 결을 따라 짧고 선명하게 나타나는 광택 |
| 잔광 | 짧게 밝아진 후 천천히 기본 색으로 복귀 |

렌티큘러는 확정 비교 시안과 같이 아이콘 너비를 세로 결 12개로 나누고, 각 결의 양 끝은 투명하게 처리한다. 각 결은 2.1초 주기로 흰색 광택의 투명도를 바꾸며 0.12초씩 시차를 둔다. 아이콘 크기에 비례해 결의 너비가 바뀌고, 화면 밖·페이지 비활성 상태에서는 결의 애니메이션도 멈춘다. 꾸미기·비교 페이지·뽑기 결과는 같은 효과 생성 함수를 사용한다.

포일은 작은 아이콘에서 흰색 면적이 과해지지 않도록 일부 면만 반짝이게 한다. 현재 시안의 주기는 5.2초, 최대 불투명도는 0.85다. 외곽선 효과와 중심을 기준으로 회전하는 효과는 채택하지 않는다. 이전 실험 페이지는 비교 자료로만 보관한다.

간섭광은 원래의 3.2초 밝기 곡선과 방사형 지점 간 0.26초 시차를 유지한다. 각 지점의 빛을 개별 반복하지 않고 한 번씩만 지나가게 하며, 마지막 빛이 사라진 뒤 약 1.12초 동안 완전히 어둡게 쉰다. 전체 반복 주기는 6.4초다. 움직임을 느리게 늘리지 않는다.

2026-11-06 최적화 비교 구현을 기본값으로 전환한다. `?renderer=optimized` 또는 쿼리 생략은 새 방식이고, `?renderer=css`·`?renderer=png`는 기존 비교 방식이다.

- 잔광·빛의 띠는 기존 CSS의 단일 흰색 레이어를 유지한다.
- 포일·렌티큘러·간섭광은 원본 밝기·무늬를 30fps의 흰색/알파 이미지에 미리 합친다. 아이콘 마스크와 기본 색상은 변경하지 않는다.
- 아이콘당 움직이는 요소는 모든 효과에서 1개다. 5종을 같은 개수로 표시할 때 100개 아이콘의 애니메이션 요소는 820개에서 100개로 감소한다. 이 수치는 DOM 애니메이션 요소 수이며 GPU 레이어 수나 발열 감소율을 뜻하지 않는다.
- 이미지 한 장을 CSS `transform`·`steps(1,end)` 키프레임으로 이동한다. 배경 위치 변경과 JavaScript 프레임 타이머는 사용하지 않는다. 투명하거나 같은 프레임은 이미지·키프레임에서 중복을 제거해 같은 위치를 유지한다.
- 생성 명령은 `npm run effects:generate`다. 추가 생성기는 `scripts/generate-badge-transform-textures.mjs`이고, 메타데이터·프레임 시간표·키프레임·해시 이미지 경로를 함께 생성한다.
- 총 411개의 시간 프레임을 373개 고유 프레임으로 저장한다. 이미지 3장 합계는 242,382바이트다. 원본 픽셀의 디코딩 RGBA 크기는 약 6MiB이며 실제 브라우저 메모리는 미측정이다.
- 원본과 모든 30fps 프레임의 알파를 대조하고, CSS 이동 좌표가 해당 프레임을 정확히 선택하는지 검증한다. 30fps 시간 표본에 따른 부드러움 차이와 마스크·합성 비용, 실제 발열 개선은 기기에서 확인해야 한다.
- 효과 비교·스트레스 테스트에 최적화/기존 CSS/기존 PNG 선택을 제공한다. 포일 정지 비교에는 최적화 열을 추가하고 공통 0.1초 시점에서 원본과 비교한다.

이전 CSS 비교 구현: 아이콘 SVG와 기본 색 마스크는 고정하고 흰색 레이어의 `opacity` 또는 `transform`만 CSS 키프레임으로 변경한다. 기본 CSS 경로에서는 PNG 프레임을 내려받지 않고 JavaScript 프레임 타이머도 돌지 않는다.

- 잔광: 흰색 레이어 1개의 투명도를 변경한다.
- 빛의 띠: 정적인 흰색 띠 SVG 이미지 1장을 고정 마스크 안에서 이동한다. 아이콘 자체는 움직이지 않는다.
- 포일: 위치와 모양이 고정된 삼각형 18개의 투명도만 변경한다.
- 렌티큘러: 정적 그라데이션을 가진 세로 결 12개의 투명도만 변경한다.
- 간섭광: 방사형 그라데이션을 정적인 기저 레이어 9개로 분리하고 각 투명도만 변경한다. `plus-lighter`로 흰색/알파를 더해 기존 그라데이션의 형태를 유지한다. 원래 속도와 빛이 없는 대기 구간을 유지한다.
- 화면 밖·수동 정지·비활성 페이지·동작 줄이기에서는 CSS 애니메이션을 정지한다. GPU 레이어를 모든 아이콘에 강제하지 않는다.
- 비교·스트레스 페이지의 CSS/PNG 선택으로 동일한 렌더러를 비교한다. `?renderer=png`는 이전 방식, `?renderer=css`는 이전 CSS 방식이다. 스트레스 개수는 10·30·100개다.
- CSS 선언이 합성 단계에서만 실행되는지, 레이어 수 증가가 메모리·발열에 어떤 영향을 주는지는 실제 기기의 프로파일링이 필요하다. CSS 방식의 발열 개선은 아직 측정하지 않았다.

이전 PNG 비교 구현: 원본 효과를 유지한 캐시 최적화: 포일의 삼각형 18개, 간섭광의 방사형 9개 지점과 시차, 렌티큘러 12개 결, 빛의 띠·잔광의 원래 주기와 밝기 곡선을 빌드 전 SVG 프레임으로 계산한다. 프레임당 64×64, 8열 격자의 투명 PNG 스프라이트 5개로 저장하고 브라우저는 흰색/알파 이미지에 아이콘 마스크만 적용한다. 색·아이콘별 효과를 다시 만들지 않는다.

- 생성 명령: `npm run effects:generate`. 생성 소스는 `scripts/lib/badge-effect-frames.mjs`이고 결과와 콘텐츠 해시 경로는 저장소에 포함한다. 사이트 실행 중 sharp나 SVG 도형 계산은 사용하지 않는다.
- 20fps, 총 396프레임이다. 5개 PNG 합계 167,350바이트이고 디코딩한 RGBA 픽셀의 이론상 크기는 6,684,672바이트(약 6.4MiB)다. 각 시트의 가로·세로는 1024픽셀 이하로 유지한다. 실제 브라우저 메모리는 별도로 측정해야 한다.
- 아이콘당 런타임 효과 요소는 자식 없는 span 1개다. SVG 면·결·그라데이션·CSS 애니메이션을 개별 실행하지 않는다.
- 페이지 전체에 타이머 1개를 두고 현재 보이는 효과 종류별 프레임을 공유한다. 100개 아이콘이어도 프레임 지정은 최대 5종 × 20fps다. 숨겨진 페이지·화면 밖·수동 정지·동작 줄이기에서는 필요한 효과가 없으면 타이머도 중지한다.
- 이미지를 각 아이콘에 마스킹·그리는 비용은 여전히 표시 개수에 비례한다. 공유된 프레임 계산이 일정하다는 것이 전체 렌더링 비용까지 일정하거나 발열이 없다는 뜻은 아니다.
- [효과 확인 페이지](https://puzzle.xivnick.me/test/achievement-badges/effect-performance/)는 화면에 보이는 5종 예시를 바로 재생하며 개별/전체 정지를 지원한다. 스크롤로 화면 밖에 나가면 공용 타이머에서 해당 효과를 제외하고 다시 들어오면 재개한다. 탭 비활성화 시에는 정지한다. [스트레스 테스트](https://puzzle.xivnick.me/test/achievement-badges/effect-stress/)는 별도 페이지에서 10개·30개·100개를 선택해 수동 재생한다. 전체 표시 개수와 화면 안에서 재생 중인 개수를 나눠 표시한다.

검증은 스프라이트 프레임의 흰색/알파와 생성 SVG의 일치, 원본 밝기 지점·면 수·결 수, 100개 공유 스케줄링, 정지 시 타이머 제거를 포함한다. 실제 브라우저 프레임 수·휴대폰 온도는 측정하지 않았다.

## 전체 완료 조건부 효과: 별빛 반짝임

완전 정복은 도전과제 목록·진행도·보상 수령에 표시하지 않는다. 해당 학기의 현재 공개 일반 문제가 1개 이상이고 전부 유효하게 완료된 동안만 효과 설정에 별빛 반짝임을 표시한다. 데일리·테스트·초안·미래 공개 문제는 대상에서 제외한다.

별빛 반짝임은 일반 효과 선택과 별도로 켜고 끈다. 선택은 계정의 장착 설정에 `all_clear_enabled`로 저장한다. 기본색·커먼에서도 사용할 수 있고 일반 에픽 효과와 함께 사용할 수 있다. 기본값은 꺼짐이다. 아이템 보유·수령·장착 이력을 새로 만들지 않는다.

새 문제가 공개되거나 완료가 제외되어 올클 조건을 잃으면 설정 항목과 실제 반짝임을 숨긴다. 저장된 켜기·끄기 선택은 지우지 않으며 다시 모두 완료하면 이전 선택을 복원한다. 새로고침·다른 페이지·일반 아이콘·색깔·효과 변경도 이 선택을 초기화하지 않는다.

아이콘 오른쪽 위의 작은 십자별이 4.2초 주기로 반짝이며 한 방향으로 180도 회전한다. 중간 90도에서 가장 밝고 커지며, 끝에서는 작고 흐려진다. 십자별은 180도 회전 대칭이므로 다음 주기로 자연스럽게 이어진다. 아이콘 해제 시에는 표시하지 않는다. 뽑기·조합 대상은 아니다.

## 표시·구현 기준

- 이름 뒤 실제 표시 크기는 18px이며 확대 시안과 함께 확인한다.
- 아이콘은 프로젝트 시안에서 사용하는 Tabler Icons의 모양을 유지한다. 아이콘 시안 12개를 업적 목록 확정으로 간주하지 않는다.
- SVG 그라데이션은 `gradientUnits="userSpaceOnUse"`와 24 × 24 좌표계를 사용한다. 수평·수직 경로가 있는 트로피 등이 누락되지 않도록 한다.
- 화면 밖과 비활성 탭에서는 효과를 멈추며, 동작 줄이기 설정과 일시정지를 지원한다.
- 테스트 페이지는 목록에 노출하지 않는다. 현재 페이지는 시각 비교용이며 실제 뽑기·재고·조합 기능은 연결하지 않았다.

### 닉네임 옆 아이콘의 공통 정렬

[NicknameBadge 컴포넌트](../src/components/NicknameBadge.astro)와 [정렬 스크립트](../src/scripts/nickname-badge-alignment.js)를 사용한다. 아이콘별 위치 보정이나 숫자 전용 크기·viewBox 예외를 두지 않는다.

- SVG의 `getBBox()`와 선 두께로 실제 그림 영역의 중심을 구한다. viewBox의 크기는 원본보다 줄이지 않고 중심만 이동하므로 기존 아이콘을 확대하지 않는다. 모든 아이콘은 같은 표시 영역에 원래 비율로 넣는다.
- 닉네임과 아이콘 기준점을 같은 글자 베이스라인에 놓는다.
- 실제 글꼴·크기·닉네임으로 `measureText()`의 `actualBoundingBoxAscent`와 `actualBoundingBoxDescent`를 읽는다. 글자 중심은 베이스라인에서 `(descent - ascent) / 2`이며, 이 위치에 아이콘 그림 중심을 맞춘다.
- 웹폰트가 로드되거나 글자 크기가 바뀌면 다시 계산한다. 같은 글꼴·문자열의 측정값은 재사용한다.

현재 적용 범위는 숫자 정렬 비교, 온도계·계산기·별 비교, 수식완성 후보 두 페이지의 이름 옆 아이콘이다. 기존 본 사이트의 배지나 효과 렌더러는 이 변경에 포함하지 않는다. [공통 정렬 시안](https://puzzle.xivnick.me/test/achievement-badges/number-alignment/)에서 12·14·16px, 한글·영문, 다른 글꼴과 여러 아이콘을 비교한다.

## 추가 결정 사항

- 뽑기 비용과 재료 수급량. 기본 뽑기 확률은 커먼 72%·레어 24%·에픽 4%로 확정한다.
- 언커먼 조합의 이름·표기 방식. 채도나 재료 비율에 따른 추가 구분 여부도 미정이며, 현재 666종 계산에는 포함하지 않는다.
- 레어와 동일한 색 조합을 가진 언커먼의 소유·도감·중복 처리.
- 에픽 효과의 적용·교체 방식. 중복은 500코인으로 바꾸며 최초 보유 효과는 유지한다.
- 기본 지급색의 최종 선택.

## 조합과 중복 처리

조합은 커먼 색깔 3개로 언커먼을 만드는 방식만 사용한다. 언커먼·레어·중복 에픽을 재료로 레어 이상을 뽑는 경로는 제거한다. 커먼 중복은 수량으로 누적한다. 언커먼·레어 중복은 100코인, 에픽 중복은 500코인을 지급하고 기존 보유 항목 1개를 유지한다. 별도 뽑기권은 사용하지 않는다. [미션 설계의 조합과 중복 보상](achievement-missions-design.md#조합과-중복-보상)을 따른다.
