# 토마토스 스도쿠 — 첫 플레이테스트

- ID: `261005_01`
- 상태: DB `test`, 공개 일시 없음
- 목표 난이도: 중간. 실제 플레이테스트 전이므로 확정 등급을 부여하지 않는다. 위치 재배치 후에는 이전 시안보다 논리 단계가 늘었다.
- 9×9 일반 스도쿠에 토마토 열 칸을 표시한다. 토마토 숫자 묶음은 `1 2 3 3 3 4 5 5 6 7`이다.
- 정답 배열과 비교하지 않고, 고정 숫자·일반 스도쿠·토마토 수량 규칙의 준수로 완료를 판정한다.

## 중심 추론

아래 좌표는 1부터 센다. 토마토는 아홉 개의 3×3 상자에 하나씩 놓고 가운데 왼쪽 상자에만 하나를 추가한다. 박스별 개수는 위에서부터 `1·1·1 / 2·1·1 / 1·1·1`이다. 첫 시안에서 왼쪽 위 상자에 네 칸이 몰린 문제를 없앤 배치다.

시작 단서만으로 토마토 중 3의 후보 위치는 r1c2, r1c9, r4c9, r8c8 네 곳이다. 1행의 두 칸에는 동시에 3을 넣을 수 없으므로 r4c9와 r8c8은 3이어야 한다. 더구나 r1c9는 r4c9와 같은 열이므로 3이 될 수 없고, r1c2도 3으로 정해진다. 이때 각 칸은 시작 시점에 일반 스도쿠의 단일 후보로 주어지지 않는다.

이외에는 8·9 제외와 한 번뿐인 숫자의 전역 후보 제거를 활용한다.

## 화면과 저장

아이콘은 칸 전체에 옅은 회색 배경으로 표시한다. 보드 위에는 숫자 묶음 `1 2 3 3 3 4 5 5 6 7`만 일반 텍스트로 고정 표시한다. 채운 칸 수, 숫자별 사용량, 취소선은 표시하지 않는다. 규정 수량 초과 및 토마토의 8·9 입력은 기존 규칙 위반 표시를 따른다.

기기 저장에는 보드 서명을 포함해 이후 단서 변경 시 이전 시안의 입력이 섞이지 않게 한다. 목록·완료 기록·클라우드는 기존 DB 공개 상태 제어를 따른다.

## 확인 범위와 후속 조정

초기 후보 관계, 규칙 위반 처리, 입력·메모·지우기·고정 숫자 보호·기기 저장 코드와 모바일 레이아웃을 확인했다. 현재 배치의 고정 숫자, 일반 스도쿠 규칙, 토마토 숫자 수량을 모두 적용한 탐색에서 해가 정확히 하나임을 확인했다.

위치 재배치 전후의 후보 소거를 비교했다. 이때 시작 숫자도 32개에서 30개로 줄었다. 일반 스도쿠의 단일 후보·숨은 단일 후보만 반복하면 이전 시안은 45칸을 채우고 4칸이 남지만, 현재 시안은 19칸을 채우고 32칸이 남는다. 토마토 숫자별 수량과 같은 숫자의 행·열·상자 중복 금지를 추가하면 이전 시안은 남은 49칸까지 모두 채워지지만, 현재 시안은 23칸을 채운 뒤 28칸이 남는다. 현재 시안은 여기에 상자와 행·열의 후보 위치를 연결하는 소거(locked candidates)를 추가하면 모든 칸이 채워진다. 이 난이도 비교는 후보 규칙에 따른 것이며, 유일성은 별도의 탐색으로 검사했다.

토마토 조건을 제외하고 고정 숫자와 일반 스도쿠 규칙만 적용하면 완성판이 최소 두 개다. 두 완성판은 r4c6·r4c9·r5c6·r5c9의 1과 3이 서로 뒤바뀌고 나머지 칸은 같다. 따라서 토마토 조건 없이는 답이 하나로 정해지지 않는다.

플레이테스트에서는 3 수량 추론의 발견 여부, 후보 위치를 연결하는 단계에서 막히는지, 실제 체감 난이도를 기록한다. 추측 없는 논리 진행은 위 범위에서 확인했지만 중간 난이도라는 체감 등급은 검증하지 않았다.
