- ID: `261111_01`
- 상태: DB `published`
- 공개 일시: 2026-11-11 00:56:02 KST · 사용자 승인 후 즉시 공개
- 목표: 데일리 일반 회차 정도의 난이도. 실제 플레이 시간과 메모량은 플레이테스트 후 조정한다.

## 데일리와의 비교 기준

`src/lib/sudoku.js`와 데일리 생성기를 기준으로 일반 기법의 범위를 맞췄다. 현재 DB에 등록된 데일리 20문제의 단서 중앙값은 24개이고, 일반 기법 점수 중앙값은 9.5다. 이 점수는 `후보 위치 연결 + 2×두 후보 묶음 + 3×숨은 두 후보 묶음 + 5×세 후보 묶음류`로 계산한다. 이 표본에서 후보 위치 연결은 16문제, 두 후보 묶음은 10문제, 숨은 두 후보 묶음은 9문제에 사용된다. 데일리에는 가벼운 회차도 포함된다.

새 빼빼로 시안은 후보 위치 연결과 두 후보 묶음을 허용하고, 세 후보 묶음이나 더 높은 기법·가정은 요구하지 않게 생성했다. 빼빼로 계산의 부담도 있으므로 일반 기법 점수는 중앙값보다 낮은 부근을 목표로 했다. 단서 개수와 기법 점수는 보조 지표이며, 변형 스도쿠의 실제 체감 난이도를 데일리와 정확히 환산하지는 않는다.

## 생성과 재현

`node scripts/generate-pepero-sudoku.mjs --seed 1111202612 --attempts 1200 --output /tmp/pepero-daily-design.json`

데일리와 같은 `generateComplete`로 완성 격자를 구성한다. 완성 격자는 생성 중 메모리에서만 사용하고 출력하지 않는다. 그 격자에서 규칙을 만족하는 빼빼로를 찾은 뒤, 가로·세로를 섞어 서로 겹치지 않는 8개를 고른다. 4칸짜리는 가로·세로 하나씩 사용한다.

3칸짜리 2개에는 숫자 두 개씩, 다른 2개에는 숫자 하나씩, 나머지 2개에는 숫자를 주지 않는다. 4칸짜리에는 숫자를 하나씩 준다. 이 배분을 유지하면서 빼빼로 밖의 단서를 하나씩 지운다. 허용한 추론으로 진행되지 않으면 지운 숫자를 복원한다. 모든 행·열·상자에 단서를 하나 이상 남긴다.

후보 위치 연결과 두 후보 묶음류가 실제로 쓰이고, 이 기법들을 제외하면 상당한 빈칸이 남는 배치를 고른다. 즉시 계산되는 빼빼로 수와 조합 추론의 부담도 제한한다. 선택한 배치는 시드의 675번째 생성 시도에서 나왔다.

## 단서와 메모 부담

숫자 두 개가 주어져 바로 계산할 수 있는 3칸짜리 2개를 쉬운 출발점으로 남겼다. 나머지 빼빼로 6개는 시작 시 계산만으로 확정되는 칸이 없다. 4칸짜리의 시작 조합은 각각 8개와 5개다.

검토 프로그램은 단일 후보와 들어갈 자리 하나를 우선하고, 길이에 따른 숫자 범위와 한 칸 계산을 사용한다. 조합 두 개 이하로 좁혀진 빼빼로를 먼저 처리한 뒤 후보 위치 연결·두 후보 묶음·숨은 두 후보 묶음을 사용한다. 필요하면 최대 여섯 조합까지 검토하도록 상한을 뒀다. 실제 선택한 배치의 조합 추론 5회는 모두 가능한 조합이 한두 개까지 좁혀진 뒤 사용된다.

3칸짜리에서는 초코의 1·2 제외와 과자의 7·8·9 제외를 활용한다. 4칸짜리에는 이 범위 제한을 적용하지 않는다. 규칙 위반과 완료 판정에서도 두 길이를 구분한다.

## 검토 결과

`node scripts/grade-pepero-sudoku.mjs`

검토 프로그램이 선택한 경로에서 다음 기법을 사용한다.

- 일반 스도쿠: 단일 후보 46칸, 들어갈 자리 하나 11칸, 후보 위치 연결 4회, 두 후보 묶음 1회.
- 빼빼로: 범위 제한 3회, 한 칸 계산 4회, 한두 조합 비교 5회.
- 일반 기법 점수: 6. 여기에 빼빼로 추론이 추가된다.

기본 스도쿠와 빼빼로 계산까지만 허용하면 39칸이 남는다. 빼빼로 없이 단일 후보·후보 위치 연결·두 후보 묶음류를 허용하면 55칸이 남는다. 일반 기법과 빼빼로 추론을 함께 사용해야 진행된다.

사용자가 요청한 유일성 조건을 새 배치에서도 독립적인 규칙 기반 탐색으로 확인했다. 해를 두 개까지 찾도록 한 전체 탐색 결과 정확히 한 개였다. 완성 답안을 게임 코드에 저장하지 않으며, 플레이 중 완료는 규칙 준수로 판정한다.

## 화면과 저장

기존 제목·요약·규칙·키패드·메모·초기화 레이아웃을 유지한다. 단색 회색 막대 안에 작은 흰색 과자 표시를 두며 둘 다 둥근 모서리로 그린다. 격자선을 막대 위에 표시하고 칸 배경과 선택 배경을 투명·반투명으로 처리한다. 별도 범례는 표시하지 않는다.

막대 두께는 0.36칸, 모서리 반지름은 0.12칸이다. 흰색 표시는 길이 0.56칸·두께 0.24칸·모서리 반지름 0.07칸이며 과자 칸의 중심에 맞춘다. 막대는 양 끝 칸 중심에서 0.34칸씩 늘려 흰색 표시가 안에 들어가게 한다. 전체 길이는 3칸짜리 2.68칸, 4칸짜리 3.68칸이다.

각 칸의 접근성 설명에서 초코·과자를 구분한다. 숫자·메모는 막대 위에 표시한다. 기기 저장에는 단서·배치 서명을 포함해 이전 시안의 입력이 섞이지 않게 한다. 2026년 11월 11일 사용자 승인으로 공개 전환했다. 목록·완료 기록·클라우드 저장은 기존 공개 상태 제어에 따라 활성화된다.


## 특수 도전과제

도전과제 `pepero`의 이름은 빼빼로데이이며, 특수 분류에 표시한다. 현재 학기 `2026-2`의 빼빼로 스도쿠 `261111_01` 하나를 완료하면 달성한다. 보상은 Tabler 원본 `number-11.svg`를 사용하는 숫자 11 아이콘(`icon:pepero`)이다. 반복 단계와 추가 코인 보상은 없다.

다른 특수 도전과제처럼 달성 후 받기 버튼으로 한 번 수령한다. 기존 완료 기록도 포함하며 제외된 기록이나 다른 퍼즐은 세지 않는다. 보유한 아이콘은 꾸미기에서 장착할 수 있다.

`python3 scripts/verify-pepero-achievement.py --rehearse`로 적용 전 전체 변경을 롤백 검증했다. 기존 기록 소급, 정확한 대상 문제, 특수 분류, 제외 기록, 미달성 수령 차단, 한 번 지급, 재요청·중복 요청, 알림과 아이콘 장착을 확인했다. 검증용 계정과 기록은 모두 롤백한다. 프런트엔드의 진행·수령 가능·수령 완료·보유·장착 매핑도 확인했다.

UI 비교 경로는 `/test/achievement-badges/pepero-mission/`이며 미완료와 달성 상태를 기존 도전과제 레이아웃으로 표시한다. 실제 도전과제는 `/nickname/`의 특수 분류에서 확인한다.
