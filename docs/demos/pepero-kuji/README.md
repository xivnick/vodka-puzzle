# 빼빼로 쿠지

운영: https://puzzle.xivnick.me/kuji/pepero-2026/

예시: https://puzzle.xivnick.me/test/pepero-kuji/

예시는 브라우저 저장소로 동작한다. 실제 계정과 완료 기록은 연결하지 않는다. 운영 DB에는 `20261111_pepero_kuji.sql`, `20261111_pepero_kuji_cutoff.sql`, `20261111_kuji_ticket_wallets.sql`을 적용했다. `20261111_publish_pepero_kuji.sql`로 단독 페이지의 실제 추첨을 활성화했다. 마이페이지 진입 버튼과 헤더 알림은 운영에 추가하지 않았다.

## DB 구조

| 테이블 | 역할 |
| --- | --- |
| `private.kuji_events` | 이벤트, 시즌·퍼즐, 완료 마감 시각, 상태(test/active/closed) |
| `private.kuji_ticket_wallets` | 이벤트·계정별 남은 참여권 수량 |
| `private.kuji_ticket_ledger` | 지급·사용 수량, 처리 후 잔액, 출처, 중복 방지 참조값, 관련 정보 |
| `private.kuji_ticket_grants` | 마감 전 완료자 10명의 최초 지급 근거. 기존 9명과 분 단위 마감 보정으로 추가된 1명 |
| `private.kuji_prizes` | 상품명·등급·표시 순서 |
| `private.kuji_tickets` | 쿠폰 번호·숨긴 상품·받은 계정·받은 시점의 닉네임·추첨 시각 |

참여권은 쿠지별 잔액으로 관리한다. 쿠지 간 잔액을 공유하지 않는다. 한 번에 여러 장 지급할 수 있고, 한 계정이 보유 수량만큼 서로 다른 쿠폰을 여러 번 뽑을 수 있다. 원장 합계가 잔액과 일치하며 직접 잔액을 수정하지 않는다.

A상 2종 각 1개, B상 5종 각 2개로 총 12장의 쿠폰을 생성하고 상품을 미리 무작위 배정했다. 상품 총수량과 남은 수량은 쿠폰 행에서 계산한다. 상품 쿠폰 수와 개인 참여권 잔액은 별개다. 전량 소진되면 참여권 잔액을 유지하고 뽑기를 중단한다.

## 지급과 구매 확장

신뢰할 수 있는 DB/서버에서만 `private.credit_kuji_tickets(event, user, amount, source, reference, metadata)`를 호출한다. 클라이언트에는 호출 권한이 없다.

| 출처 | 참조값 예 |
| --- | --- |
| `completion` | 퍼즐 완료 보상 식별자 |
| `reward` | 미션·이벤트 보상 식별자 |
| `purchase` | 결제가 검증된 주문 또는 주문 항목 식별자 |
| `admin` | 운영 지급 작업 식별자 |
| `refund` | 사용한 참여권을 복구하는 작업 식별자 |
| `draw` | 소비한 상품 쿠폰 번호. 추첨 RPC만 기록 |

`(event_id, source, reference)`를 유일하게 관리한다. 같은 지급·주문을 재처리하면 추가 지급하지 않고 현재 잔액을 반환한다. 같은 참조값의 계정·수량·관련 정보가 다르면 오류를 반환한다. 출처별 참조값은 같은 쿠지 안에서 재사용하지 않는다.

구매 출처와 주문 추적 구조만 준비한 상태다. 가격·구매 UI·코인 차감·결제 승인·현금 환불은 구현하지 않았다. 결제 수단을 정하면 검증된 결제 완료 처리에서 지급 함수를 연결한다. 코인 구매는 코인 차감과 참여권 지급을 같은 DB 트랜잭션으로 묶어야 한다. 외부 결제는 결제 검증 후 안정적인 주문 식별자로 지급을 재시도한다.

## 빼빼로 지급 조건

한국 시간 2026-11-11 오전 11:11분까지(11:12:00 미만) 빼빼로 스도쿠를 완료한 Google 계정 10개에 각 1장 지급했다. 초기에는 11:11:00으로 해석해 9명만 지급했으나 `20261111_pepero_kuji_cutoff_minute.sql`로 11:11:59.999999까지 포함하고 11:11:52 완료자 1명을 추가했다. 기존 지급·사용 내역은 보존하며, 이미 지급한 계정에는 중복 지급하지 않는다. 이후 완료에 따른 자동 지급은 없다.

빼빼로 쿠지는 추첨 시에도 마감 전 완료 기록이 제외되지 않았는지 확인한다. 잔액 구조를 확장해도 대상자 제한은 바뀌지 않는다. 추후 완료 조건 없이 티켓으로만 참여하는 쿠지는 `eligibility_cutoff=NULL`로 구성할 수 있다.

## 추첨과 재시도

`kuji_context(event)`는 상품별 수량·티켓 상태·본인 남은 참여권(`remaining_tickets`: 0 이상의 정수)을 반환한다. 미개봉 쿠폰의 상품 정보와 계정 UUID는 반환하지 않는다.

`open_kuji_ticket(event, number)`는 로그인·이벤트 상태·참여 조건·잔액·쿠폰 상태를 확인한다. 이벤트 행을 잠근 뒤 잔액 1장 차감, 쿠폰 수령 기록, 원장 사용 기록을 한 트랜잭션으로 처리한다. 실패한 요청은 잔액을 소비하지 않는다.

같은 쿠폰 번호 재요청은 이미 받은 결과를 반환하고 중복 차감하지 않는다. 다른 쿠폰 번호는 새로운 1회 추첨이며 참여권 1장이 더 필요하다. 계정당 1회 유일 제약은 제거했다. 이벤트 잠금과 잔액 음수 방지 제약으로 동시 요청을 직렬화한다.

받은 계정이 삭제되어도 쿠폰은 개봉 상태로 유지한다. 닉네임은 수령 당시 값으로 보관한다. 계정의 지갑과 원장은 계정 삭제 시 함께 삭제된다. 과거 지급 시각과 완료 근거는 이전 기록 및 이전 원장의 관련 정보에 보존한다.

운영 화면은 서버에서 받은 잔액과 상품을 표시한다. 연출이 끝난 뒤 아래에 본인 결과를 추가하며, 여러 장 사용 시 모든 본인 결과가 남는다. 표시 이름과 상품명은 HTML로 해석되지 않게 처리한다. 선택한 쿠폰 번호는 계정·이벤트별 세션 저장소에 보관한다. 응답 유실 시 결과를 재조회하고 필요하면 같은 쿠폰만 재요청하므로 중복 소모하지 않는다. RPC는 15초 제한을 두고, 사용자가 다시 확인할 수 있게 한다. 30초 및 화면 복귀 시 다른 사람의 추첨을 갱신한다. 예시 화면은 계속 브라우저 저장소로만 동작한다.

## 검증

`python3 scripts/verify-pepero-kuji.py`는 독립적인 임시 이벤트·계정을 트랜잭션 안에서 만들고 검증한 뒤 롤백한다. 여러 장 지급·반복 추첨·동일 쿠폰 재요청·0잔액·쿠폰 충돌·주문 중복 및 계정 변경 방지·쿠지 간 잔액 분리·소진 후 잔액 유지·마감 조건·직접 접근 권한·원장 합계를 확인한다.

초기 마이그레이션 적용 전에는 `--rehearse`로 최초 구조부터 분 단위 마감 보정까지 포함해 검증한다. 분 단위 마감 보정 전에는 `--rehearse-minute`로 검증한다. 기존 1장 구조에서 지갑으로 바꾸기 전에는 `--rehearse-wallets`로 새 마이그레이션만 포함한다. 검증에 사용한 계정과 추첨은 남기지 않는다.

`node scripts/verify-kuji-client.mjs`는 실제 계정 없이 서버 결과 사용·이름 이스케이프·티켓 공개 후 결과 추가·다회 추첨·중복 클릭·응답 유실 후 같은 쿠폰 복구·새로고침 결과 복구·비로그인 조회를 확인한다. 운영 페이지 배포 후 DB 활성화를 진행하고 공개 RPC로 미개봉 정보 비공개와 비로그인 추첨 차단을 확인한다.

## 명시적으로 요청된 테스트 추첨 초기화

`python3 scripts/reset-kuji-test-draws.py --event pepero-2026 --nickname '<닉네임>' --numbers <번호>`로 지정한 계정·쿠폰만 되돌린다. 먼저 `--dry-run`으로 롤백 검증한다. 전체 이벤트 초기화로 사용하지 않는다.

실행 전 개인 지갑·추첨·원장을 `~/Documents/Backups/vodka-puzzle/kuji-test-resets/`의 비공개 파일로 백업한다. 이벤트 잠금 안에서 수령자와 원래 차감 기록을 확인하고, 원래 차감은 reset 식별자로 보존한 뒤 연결된 `refund` 원장을 추가해 사용한 티켓을 복구한다. 선택한 쿠폰의 수령 정보만 비우고 상품 배정은 유지한다. 이전 차감 참조값은 보존 정보에 남기면서 쿠폰 번호 참조를 비워 재추첨할 수 있게 한다. 관련 없는 쿠폰과 다른 계정 지갑이 바뀌지 않았는지, 잔액과 원장 합계가 일치하는지 확인한다. 실패하면 모두 롤백한다.
