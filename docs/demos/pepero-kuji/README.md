# 빼빼로 쿠지

예시: https://puzzle.xivnick.me/test/pepero-kuji/

예시는 브라우저 저장소로 동작한다. 실제 계정과 완료 기록은 연결하지 않는다. DB 마이그레이션은 `supabase/migrations/20261111_pepero_kuji.sql`에 준비하며 운영 DB에는 적용하지 않는다.

## DB 구조

| 테이블 | 역할 |
| --- | --- |
| `private.kuji_events` | 이벤트, 대상 시즌·퍼즐, 상태(test/active/closed) |
| `private.kuji_prizes` | 상품명·등급·표시 순서 |
| `private.kuji_tickets` | 쿠폰 번호·숨긴 상품·받은 계정·받은 시점의 닉네임·추첨 시각 |

A상 2종 각 1개, B상 5종 각 2개로 총 12장을 생성하고 상품을 무작위 배정한다. 참가 인원을 미리 등록하지 않는다. 수량은 티켓 행 수로 관리하며 총수량과 남은 수량을 따로 저장하지 않는다.

`kuji_context(event)`는 상품별 수량과 티켓 상태를 반환한다. 미개봉 티켓의 상품 정보와 계정 UUID는 반환하지 않는다. `open_kuji_ticket(event, number)`는 Google 로그인과 `261111_01`의 제외되지 않은 완료 기록을 확인하고 선택한 쿠폰을 개봉한다.

이벤트 행 잠금으로 동시 추첨을 직렬화하고, `(event_id, claimed_by)` 유일 제약으로 계정당 1회를 보장한다. 재시도는 기존 결과를 반환하며 다른 쿠폰을 다시 열지 않는다. 받은 계정이 삭제되어도 티켓은 개봉 상태로 유지한다. 닉네임은 수령 당시 값으로 보관한다. 상품 테이블과 티켓 테이블은 브라우저에서 직접 읽거나 수정할 수 없다.

운영 연결 시 마이그레이션을 적용하고 별도 승인으로 이벤트를 `active`로 전환한다. 초기 상태는 `test`이며 공개 RPC로 접근할 수 없다. 클라이언트는 추첨 전에 결과를 결정하지 않고 RPC에서 받은 결과로 연출한다. 네트워크가 끊기면 context를 다시 조회해 본인의 결과를 복구한다.

`python3 scripts/verify-pepero-kuji.py`는 마이그레이션·권한·미개봉 상품 비공개·완료 조건·중복 요청·품절 쿠폰 충돌·결과 복구를 트랜잭션 안에서 확인한 뒤 모두 롤백한다. 운영 테이블과 이벤트를 남기지 않는다.
